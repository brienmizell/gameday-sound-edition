# The Sound Edition — data contract

This directory is the **only** interface between GameDay (this repo, a static
site) and the music system (`briens-mac-mini.local:~/musicsystem`).

The music system **writes** these files. GameDay only **reads** them.
Neither side imports the other's code. That is deliberate: it is what lets the
schedule app ship now and the music layer land later without a rewrite.

---

## Files

| file | who writes it | what it is |
|---|---|---|
| `index.json` | music system | the list of matchups that have an issue |
| `<slug>.json` | music system | one full issue |

An absent or empty `index.json` is a **valid state**, not an error. It means
"no issues yet," which is correct for every week until the music side runs.
Every card then renders its Sound slot as `No issue yet`.

---

## The slug

Generated by `matchupSlug()` in `src/sound.js`. The music system must produce
the identical string or the issue will not attach to its card:

```
<season>-w<week padded to 2>-<away shortDisplayName>-at-<home shortDisplayName>
```

Lowercased, every run of non-alphanumerics collapsed to a single `-`, leading
and trailing `-` stripped.

```
2026-w01-colorado-at-georgia-tech
2026-w06-georgia-at-alabama
```

## `index.json`

Kept small — it loads on every page view.

```json
{
  "issues": [
    {
      "slug": "2026-w01-colorado-at-georgia-tech",
      "title": "GameDay No. 1: the ranch and the parking deck",
      "trackCount": 21,
      "status": "pressed"
    }
  ]
}
```

`status`: `pressed` | `held` | `field-note`.
`held` means the playlist was not placed (dead Spotify session, matcher miss).
`field-note` means the set did not play as music and shipped as prose only —
a success under the musicsystem rules, not a miss.

## `<slug>.json`

```json
{
  "slug": "2026-w01-colorado-at-georgia-tech",
  "title": "GameDay No. 1: the ranch and the parking deck",
  "masthead": "21 tracks · 2026 Week 1 · Thu 3 Sep, Bobby Dodd Stadium, Atlanta GA",
  "declaration": "60-110 words. What this issue argues and why these two towns.",
  "status": "pressed",
  "playlistUrl": "https://open.spotify.com/playlist/...",
  "writeupUrl": "https://.../writeups/gameday-2026-w01-....md",

  "sides": {
    "away": { "school": "Colorado", "town": "Boulder, CO", "scene": "the musical history of this side", "plays": 238 },
    "home": { "school": "Georgia Tech", "town": "Atlanta, GA", "scene": "the musical history of this side", "plays": 1498 }
  },

  "neutralField": "Where the two histories actually touch. Empty string if they never do.",

  "tracks": [
    {
      "n": 1,
      "artist": "Artist",
      "title": "Title",
      "year": 1974,
      "side": "home",
      "tier": "T2",
      "receipt": "the fact that earns the seat",
      "plays": 12,
      "note": "40-90 words carrying one load-bearing fact and one job in the argument.",
      "spotifyUrl": "https://open.spotify.com/track/..."
    }
  ],

  "sources": ["itemized, by kind"]
}
```

### Field rules

- **`side`** — `home` | `away` | `neutral` | `tailgate`. Anything else is
  coerced to `neutral`.
- **`tier`** — the reach ladder, free text but conventionally:
  `T0` town · `T1` enrollment · `T2` the room (studio/label/venue) ·
  `T3` stadium canon · `T4` diaspora. Rendered as a small badge.
- **`receipt`** — the verifiable fact. Rendered in italic under the note.
  This is the field that keeps the format honest; do not leave it blank.
- **`plays`** — count from the listening ledger, or `null`. Rendered only
  when non-zero, so a canon track with no plays simply omits it.
- **`n`** — playlist position. Should equal the Spotify running order.

### Validation

`validate()` in `src/sound.js` is structural and forgiving by design: a track
missing `artist` or `title` is **dropped and counted**, not fatal, and the
reader shows a collapsed `data warnings` block. A bad write from the other
machine degrades this page; it never breaks it.

## Adding an issue by hand

1. Write `data/sound/<slug>.json`.
2. Add its row to `data/sound/index.json`.
3. Reload. No build, no restart.
